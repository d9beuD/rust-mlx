# Rust-MLX

Read docs/architecture.md, docs/research-log.md and GATES.md before changing inference. This is one Cargo package, using mlx-rs 0.32.0 and mlx-sys 0.6.0 (MLX 0.32.2). Safe Rust owns graphs and state; unsafe is confined to the MLX C boundary and every unsafe block must explain ownership/lifetime and bounds with SAFETY. Never fork MLX or build a C++ bridge without a measured missing capability.

Build with Xcode + Metal toolchain and CMake. In this workspace CMake is provided by .venv/bin; use `PATH="$PWD/.venv/bin:$PATH" cargo build --release`. Python is a research oracle only.

Required checks: cargo fmt --check; cargo clippy --workspace --all-targets --all-features -- -D warnings; cargo test --workspace --release. Run scripts/check.sh with CMake on PATH. Test every new custom kernel against native MLX, including the actual bf16 model shapes, then microbenchmark and end-to-end A/B. Experimental paths never become default on microbench evidence alone. Keep a native MLX reference fallback.

Record successes and failures in docs/research-log.md with exact commands and commit. Raw reports belong in results, including model, mixed quantization, hardware, macOS, MLX, prompt/output IDs, lengths, MTP, sampler, cache, repetitions and variance. Warm-up then alternate baseline/candidate. Below 2% end-to-end can be noise; aim for >=5%. Never compare cached-prefix performance as raw model speed.

Requested model is 106 GB qwen4_exp with 48 hybrid layers, zero-centered grouped RMS norms, 512 experts, 10 active, n-gram PLE sharded table, QSA and MTP. The checkpoint already uses sanitized language_model.model.*, mtp.* and vision_tower.* keys. Each module may have its own bits/group size. Vision is outside the first text inference milestone. CPU mmap PLE rows should avoid materializing the entire n-gram table on GPU. Exact distribution and cache commit/rollback take priority over performance.

Do not stop or modify unrelated user processes. Existing oMLX on port 8001 requires authentication; avoid reading secrets. Record competing workloads when measuring.

Current validated defaults: exact greedy MTP depth3, selected short-row shared QMV, restricted combined HC down/inject, compatible batch-row QMV. Native fallbacks: RUST_MLX_VERIFY_QMV=0, RUST_MLX_HC_PROJECTION=0, RUST_MLX_BATCH_QMV=0. Final raw medians46.38 plain/70.37 MTP; batch8 median106.55 aggregate (13.32 per conversation). Never present aggregate100 as single-conversation100. See docs/performance.md and results/performance-summary.json for complete samples/cohorts.

Precision rules learned from the target: preserve zero-centered gamma+1 inside the compiled norm boundary and explicit BF16 cast points; F32 GDN a/b projections use singleton-equivalent row reductions. Multi-token verification needs state histories (verification::active), while independent batch rows need only projection geometry (verification::rows). HyperPlan cache keys include kernel/mode controls. Do not reuse a compiled graph across changed dispatch policy. The experimental unquantized GEMV accepts only already evaluated row-contiguous weights: lazy views can advertise provisional strides, so use the pinned MLX-C availability/layout flags in src/metal.rs, not guessed strides or implicit GPU synchronization.

Serving has one owning MLX thread, strict greedy text API, bounded queues and cancellation-aware complete UTF-8 finalization. Optional --no-mtp --batch-size8 groups equal cache offsets and preserves independent PLE/KV/GDN state. MTP batching and partial-prefix reuse are not implemented. Exact-prompt LRU is model-scoped4 entries/8192 tokens; prepared hidden retains the prompt for MTP priming. Never send MLX tensors/kernels through Tokio channels. scripts/server_smoke.py, server_batch_smoke.py and server_utf8_smoke.py exercise actual default binaries; cancellation must preserve other active clients' trajectories.

Measured rejected defaults: streamed-x QMV, fused MoE, packed GDN, async layers, whole-HC compile, batched PLE decode, static/refreshed draft shortlists and shared unquantized GEMV. Some are exact and locally useful, but do not pass the global >=5% end-to-end gate. Keep evidence and switches; do not reactivate them on component numbers. Native/adapted competitors must match logits/IDs before timing. MTPLX/oMLX research adapters currently fail canonical prefill logits on this checkpoint; this is not a claim about their stock products.

Final quality evidence:16 release tests plus strict Clippy/format;15 separate instrumented Metal kernel tests. scripts/validate-metal.sh enables process-local GPU validation with stderr reporting and abort-on-fault, outside throughput runs. results/quality-current.json records a source checksum: recheck after actual core changes, not documentation-only updates. GPU capture/profile artifacts can be large and stay ignored; component capture covers only the head. Full-model instrumentation changes scheduling and must never enter performance-summary.json.
